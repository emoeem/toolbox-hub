**标题**：我把命令行工具包装成了「能填表的工具箱」，还给它配了个 `Ctrl-G`

**副标题**：记不住参数不是你的问题，是工具没给你提示

## 引子：我为什么又写了一个 TUI

`ffmpeg` 抽音轨那条命令，我查了至少十次。`yt-dlp` 的格式选择、`pandoc` 的一堆开关、
`tar` 到底是 `-xzf` 还是 `-xjf` —— 每次都要 `--help` 翻半天，或者去搜「xxx 命令 复制」。

我需要的不是「又一个命令行工具」，而是**把我已经装好的那些工具，按我心里的分类摆出来，
点一下、填两个字段、回车**。剩下的还是那些工具自己在干。

⟨截图 1：主界面，域标签 + 工具列表 + 右侧状态行⟩

## 一、它长什么样

顶上一排是域（媒体 / 图像 / 系统 / 网络 / 开发 / 工具 / 包管理 / 打包），中间是工具列表，
选中哪个右边就显示它要什么参数。回车弹表单，填完执行，输出进历史 —— 下次还能翻出来重跑。

它认得三类东西：

1. **内置动作**：写在 TOML manifest 里，比如「H.264 + CRF 重编码」；
2. **你自己的脚本**：丢进 `~/.config/toolbox-hub/tools/`，文件头写几行注解就能被发现；
3. **远程工具包**：`toolbox-hub install ffmpeg-extra-recipes` 这种，装上就出现在列表里。

⟨截图 2：一个表单（推荐用 ffmpeg 转码那个，字段多、看得出「填表」的价值）⟩

## 二、这轮最值得说的：`Ctrl-G`

装了 shell 集成之后，终端里按 `Ctrl-G` 会弹出命令选择器：

```bash
eval "$(toolbox-hub widget bash)"     # zsh / fish 的写法在 README 里
```

⟨截图 3：按 Ctrl-G 后的选择器⟩

它和「命令别名」「历史搜索」不一样的地方在于：**选中的命令是填到你正在输入的那一行**，
不是直接执行。所以你可以先填一半、改个路径、再回车。历史记录里留下的是真实命令，
不是包装工具的名字 —— 这一点我在实现时特意保证了。

## 三、速查表也能用：三种格式导入

如果你有 navi / cheat / tldr 的速查表，可以导进来：

```bash
toolbox-hub import navi ~/.config/navi/cheats/ffmpeg.cheat --dry-run
```

有意思的是它**不是照单全收**。每条会被分成三类：

- **可导入**：能安全拆成「程序 + 参数模板」，比如 `ls -la <path>`；
- **仅展示**：带管道、重定向、`$(...)` 的 —— 从字符串还原 shell 语义一定会出错，
  所以只告诉你「这条存在，但得你自己看着办」；
- **跳过**：命中危险命令的。

`--dry-run` 先看一眼它打算怎么办，不满意就不落盘。

## 四、两个不显眼但重要的细节

**视频预览**：`F` 视图里选中 mp4 现在会显示第一帧（调 ffmpeg 抓的），并且**缓存在磁盘上**，
翻来翻去不会反复起 ffmpeg。缓存会自己限量和清理，整个目录随时可以删。

**危险动作要过三道门**：标记为破坏性的 Recipe 默认跑不了，需要显式确认 + 一段审计说明 + 环境变量
三者齐备。它靠的是规则式黑名单，**不是沙箱** —— 拦得住 `rm -rf`，拦不住 `xargs rm -rf`。
README 里把两种清单都列了，用之前值得看一眼。

## 六、它现在还不够好的地方

- 只支持 Linux，而且默认构建**动态链接 libalpm**，所以完整功能是 Arch 向的；
- zsh 集成脚本写好了，但我没有 zsh 环境实测（bash 和 fish 是实测过的）；
- 队列是串行的：一次跑一个后台任务；
- 还没正式发过 Release。

这些我都写在仓库的「已知局限」一节里，不打算藏。
